## 1. 遊戲名稱與主題風格

### 1.1 名稱
**MNEMO・VERSE：數字轉生**（英文 sub：*Numbers, Reborn in Space*）

「轉生」一詞同時吃兩層意思：數字**轉碼**成圖像、數字在 3D 空間中**再生**為生物／物件。學生第一次看到 `04` 融成一隻發光水母時，記憶鉤子就已經釘進去了。

### 1.2 主題：深空編碼艙（Deep-Space Encoding Pod）
現有場景是深藍霓虹星空 + 徑向光暈（`spatial-shell` 漸層 + `Stars` + `Sparkles`），本企劃保留此為預設世界，並擴充為**三套可切換 World Skin**，與現有八天賦／VARK 系統掛勾：

| Skin | 視覺設定 | 材質語言 | 對應天賦 | 效能 |
|---|---|---|---|---|
| **A. NEON VOID**（預設 ✅） | 賽博深空，霓虹發光體浮在星塵中，掃描線與 grid 地平線 | 自發光玻璃 + 霓虹邊緣光 | 探索者 / 機器人向的 analyst、performer | 中 |
| **B. DREAM GALLERY** 🆕 | 超現實夢境藝廊：無限白空間、柔和天光、數字像美術館展品懸浮於基座上 | 水晶、磨砂玻璃、液態金屬 | visionary（圖像家）、architect（建築師） | 高（需 HDRI + DOF）|
| **C. LOW-POLY FABLE** 🆕 | 低多邊形奇幻世界，色塊分明、卡通描邊、無反射 | flat shading，硬邊陰影 | narrator（敘事者）、melodist；**也是低階裝置的自動降級目標** | 低 |

> 現有 `detectLowPowerDevice()` 已能偵測 `hardwareConcurrency ≤ 4 / deviceMemory ≤ 4 / prefers-reduced-motion`。建議把「low 畫質」從「同場景減效果」升級成「切換到 Low-Poly Skin」——低階裝置得到的不是殘缺版，而是另一種完整美術風格。這對教學現場（學校電腦、平板）非常關鍵。

### 1.3 色彩系統
每一組數字帶有專屬 `palette`（已實作，以 CSS 變數 `--round-color` 貫穿 UI 與 3D 燈光）。v2 讓這個顏色進一步驅動：環境光色溫、Bloom 色偏、粒子色、UI 邊框、甚至 combo 音效的音高。**單一資料來源 → 全場感官同步**，是沉浸感最便宜也最有效的做法。

## 2. 3D 互動遊戲流程（3D Game Loop）

整體結構沿用現有四階段：`encode`（10 組編碼）→ `interference`（注意力干擾閘）→ `recall`（延遲回想）→ `result`（記憶分析）。
這個結構本身在教學上是對的：**編碼 → 干擾 → 延遲提取**，才測得到真正的長期記憶，而不是工作記憶殘影。v2 主要強化的是 `encode` 階段的 3D 鏡頭語言。

### 2.1 單回合六拍（Encode Beat Sheet）

| 拍 | 名稱 | 時長 | 鏡頭語言 | 場景事件 | 狀態 |
|---|---|---|---|---|---|
| **0** | POD ENTRY 進艙 | 0.8s | Dolly-in，FOV 52°→42° | 艙門光圈開啟，環境音淡入 | 🆕 |
| **1** | SPAWN 進場 | 1.2s | 相機固定，物件從 `z = -40` 帶 motion trail 飛來，於 `z = -2` 急停 + 5% overshoot（彈性 easing） | 數字以該組材質浮現，星塵被推開產生尾流 | 🔶 現為直接出現 |
| **2** | INSPECT 觀察 | 自由 | OrbitControls，玩家拖曳旋轉 ✅ | **隱藏線索**：rim light 掃過特定角度時，數字側面才顯現筆畫暗示（例：`31` 轉到 45° 才看見鰭狀輪廓）🆕 | 🔶 |
| **3** | LOCK-ON 瞄準 | 0.6s | 3D 準心貼齊 anchor 點 ✅（`Crosshair`），停留 0.6s 觸發鎖定 | 色差（chromatic aberration）向中心收縮，鎖定音效 | 🔶 現為靜態準心 |
| **4** | INPUT 輸入 | 自由 | **Zoom-in**：`camera.z 8.4 → 5.6` damp ✅ | 背景景深加深、環境光降至 60%、UI 側欄亮起輸入框 | ✅ |
| **5** | MORPH 變身 | 1.2s | Orbit 環繞 30°，輕微手持感 | 見下方三段式變形 | 🔶 |
| **6** | SETTLE 結算 | 1.0s | 拉回 wide shot | 分數浮現、combo 判定、下一艙預載 | ✅ |

### 2.2 MORPH 三段式（拍 5 細節）

```
0.00 – 0.25s  FRACTURE 裂解
              數字表面沿 UV 裂開，邊緣自發光升溫（emissive 由 palette → 白）
              morphTargetInfluences 0 → 0.3

0.25 – 0.70s  DISSOLVE + BRIDGE 溶解與橋接
              數字實體 opacity → 0.08（已實作的 MorphTargetCore 邏輯）
              同時噴出 2000~4000 粒子，粒子沿 curl-noise 流向目標物件的表面取樣點
              ⇒ 視覺上是「數字的物質被搬運去組成新物件」，不是換模型

0.70 – 1.20s  REBIRTH 重生
              目標物件由內而外浮現（Fresnel 邊緣先亮）
              播放專屬 idle 動畫（水母脈動、鯊魚繞場、鐵塔煙火）
              殘餘粒子回落成環繞光塵
```

**設計要點**：粒子橋接是讓「數字 → 圖像」這件事在感官上被證明的關鍵。學生看到的不是兩個東西切換，而是同一團物質的轉世——這正是數字轉碼法要建立的心智模型。

### 2.3 Combo 與空間沉浸

| Combo | 觸發效果 | 狀態 |
|---|---|---|
| 1 | 分數浮字 + 粒子小爆 | ✅ |
| 2 | Camera shake 0.42s ✅ + 低頻音效 | ✅ |
| 3 | **環境光色溫位移**至該組 palette，整個艙體染色 | 🔶 |
| 4 | Combo 粒子環（orbit ring）繞玩家旋轉，持續到斷連 | 🆕 |
| 5+ | **OVERDRIVE**：Bloom 強度 +60%、時間輕微變慢（0.85x）、星空加速流動 | 🆕 |

Combo 判定沿用現有 `scoreAssociation()`：命中 alias 得 76 分底，含動態詞彙（爆/飛/游/跳/燃/光/融/碎…）+14，長度加成上限 10，≥70 分續連。
🆕 建議加第三個維度：**首次使用的新詞**額外 +8，鼓勵學生自己造聯想而非背標準答案。

### 2.4 干擾關與回想艙（已實作，維持）

- **DISTRACTION GATE** ✅：四選一找出「不屬於轉碼流程」的選項，目的是清空工作記憶。
- **RECALL POD** ✅：同一 3D 場景，但**隱藏數字與聯想詞**，燈光轉為冷色單光源、物件只剩剪影＋輪廓光，玩家看物件反推兩位數，記錄反應時間。
- 🆕 建議：回想艙的物件加入「緩慢自轉」而非玩家可控——移除空間操作，逼迫從記憶提取而非重新觀察。

## 4. 3D 技術實現建議

### 4.1 現有堆疊評估（先講結論：底子很好，不用重寫）

| 項目 | 現況 | 評價 |
|---|---|---|
| 渲染 | `@react-three/fiber` 8.18 + `three` 0.179 + `@react-three/drei` 9.122 | ✅ 正確選擇，React 生態整合最佳 |
| 數字模型 | `Text3D` + `helvetiker` font，bevel 開啟 | ✅ 零資產成本，適合 100 組擴充 |
| 形變 | `geometry.morphAttributes.position` + `morphTargetInfluences` damp | 🔶 可用，但受限於頂點數必須相同 |
| 目標物件 | 10 個手刻 primitive 組合（`Jellyfish`、`Shark`…） | 🔶 快速但精緻度有限 |
| 粒子 | `THREE.Points` + `PointsMaterial` | 🔶 夠用，數量上不去 |
| 相機 | 手刻 `MathUtils.damp` + shake impulse | ✅ 輕量有效 |
| 效能 | `dpr` clamp、`frameloop: demand`、quality 三檔、`lazy` + `Suspense` | ✅ 做得比多數 side project 好 |

### 4.2 Morph Targets：兩條路線

**問題**：Three.js 的 morph target 要求來源與目標**頂點數與順序完全一致**。`Text3D` 產生的幾何體頂點數依字形而異，硬對齊會扭曲。現有 `cachedMorphGeometry()` 是聰明的權宜之計，但擴充到 100 組會撞牆。

- **路線 A｜Blender Shape Keys（品質優先）**
  Blender 中建立 base mesh（數字）→ 複製為 Shape Key 並雕塑成目標物件 → 匯出 glTF（Draco 壓縮）→ `gltfjsx` 轉 R3F 元件。頂點對應由 Blender 保證。
  適合：主打的 10~20 組明星數字。
  成本：每組約 1~2 小時建模。

- **路線 B｜Shader 粒子轉場（擴充性優先）🆕 推薦**
  完全繞開頂點數限制：兩個模型各自用 `MeshSurfaceSampler` 取樣出 N 個表面點（N 固定，例如 8192），在 vertex shader 中以 `uProgress` 對兩組位置做 lerp，並疊加 curl noise 產生流動感。
  ```glsl
  vec3 pos = mix(aFrom, aTo, smoothstep(0.0, 1.0, uProgress));
  pos += curlNoise(aFrom * 0.4 + uTime * 0.2) * (1.0 - abs(uProgress * 2.0 - 1.0)) * 0.9;
  ```
  中間段偏移最大 → 天然形成「爆散再聚合」的視覺，正好就是 §2.2 的 BRIDGE 效果。
  **優勢**：任何模型對任何模型都能轉，100 組不需要 100 次手工對齊。

  實務上建議 **A + B 混用**：實體用 A 做精緻 morph，粒子層用 B 做橋接，兩者同時播放。

| 效果 | 用途 | Low-Poly Skin |

| `Bloom` | 霓虹自發光、combo overdrive | 關閉 |

### 4.4 100 組數字的程序化生成 🆕

不建模 100 個物件也能覆蓋整本 CODEBOOK：

1. **語意 → 幾何模板**：把 100 個聯想詞分類到 ~12 個原型（生物體 / 建築 / 載具 / 人物 / 食物 / 工具 / 自然 / 抽象…），每個原型一組參數化 mesh。
2. **參數化差異**：以 code 為 seed 決定比例、分支數、顏色、材質粗糙度。`51 狐狸` 與 `31 鯊魚` 共用「生物體」模板，靠參數分化。
3. **明星組手工升級**：學生最常用、最難記的 10~20 組才手工建模。
4. **玩家自訂**：允許學生替換自己的聯想詞（現有 CODEBOOK 已鼓勵「換成你自己的角色」）——這時只能用程序化生成，模板方案剛好接得上。

### 4.5 動畫排程

現有手刻 `MathUtils.damp` 對單一屬性很好用，但六拍時間軸建議引入時間線工具：

- `@react-spring/three`：宣告式，與 React state 對齊，適合 UI 驅動的過場。
- **GSAP timeline**（推薦用於 MORPH 三段式）：`.to()` 串接、`onUpdate` 寫入 uniform，時間點精準可調，美術可獨立微調參數而不動邏輯。

### 4.6 音效（目前缺口）🔶

現有 `speechSynthesis` 只在 2D 故事挑戰用。3D 場景建議加 `PositionalAudio`：

- 數字飛來時的都卜勒風切（跟隨 `z` 位置變化 pitch）
- MORPH 三段各一層音（裂解「喀」→ 溶解「嘶」→ 重生和弦）
- Combo 音高隨連擊數升 semitone，5 連時解鎖低音層 → 聽覺型（melodist / auditory）學生的主要回饋管道
- 回想艙全靜音，只留環境嗡鳴——安靜本身就是「這裡沒有提示」的訊號

### 4.7 效能守則（延續現有良好實踐）

- 幾何體與材質 `useMemo` 快取，跨 round 重用（`cachedMorphGeometry` 已這樣做 ✅）
- 下一 round 的模型在當前 round 的 INSPECT 階段預載（玩家在思考，GPU 閒著）
- `frameloop: 'demand'` 於 low 模式 ✅；回想艙可全程 demand（畫面幾乎靜態）
- 尊重 `prefers-reduced-motion` ✅：關閉 camera shake 與時間縮放，改用色彩閃爍替代回饋
- 目標：中階筆電 60fps、iPad 第 9 代 30fps、教室文書機 fallback 到 Low-Poly Skin 30fps

## 附：教學設計理據

這款遊戲之所以不只是「炫技」，在於三個結構：

1. **雙重編碼（Dual Coding）**：文字聯想 + 3D 視覺同時建立，兩條提取路徑。
2. **主動生成效應（Generation Effect）**：學生必須自己輸入聯想詞才觸發變形，而非被動觀看——現有 `scoreAssociation` 對「新連結」也給分，正是在保護這一點。
3. **延遲提取 + 干擾（Desirable Difficulty）**：`interference` 關卡刻意清空工作記憶，使 `recall` 測到的是真正的長期記憶。這是現有實作中最有教學價值的設計，v2 完整保留。

3D 的作用不是好看，而是提供**空間索引**——記憶宮殿法的核心機制。物件在空間中的位置、朝向、你繞著它轉過的角度，全都成為額外的提取線索。
