# 陸行鳥外交巡迴賽 3D — 架構說明

`/race`。一個用 three.js 即時渲染的騎乘鳥賽車模式，同時是 fluent-ai 的語言關卡：
**賽道就是國家，對手就是各國代表，賽道上的閘門就是題目**。
場景、座騎、賽道全部由程式產生，沒有任何外部模型或貼圖檔。

## 玩法一句話

三條車道各掛一塊看板，上面是三個候選答案；**你開過哪條車道就是你的答案**。
答對加速 1 秒、回體力；答錯掉 18% 速度；繞過閘門則不計分。全程不暫停、不跳出視窗。

角色是 fluent-ai 派出的通譯官，一路從「見習通譯」升到「大使」。

## 座標系與慣例（很重要）

three.js 是右手系：一隻**面向 +Z** 的鳥，牠的右手邊在 **-X**。
因此賽道採樣點的 `right = forward × up = (-dir.z, dir.x)`，而**方向盤往右是 yaw 遞減**。

這件事一開始寫反了，造成三個症狀同時發生：按 D 往左轉、閘門看板左右顛倒、
HUD 的「左／中／右」和玩家看到的相反。現在有兩個測試把它釘住：

- `track.test.ts`：每個採樣點的 `right` 必須等於 `forward × up` 的外積。
- `race.test.ts`：面向 +Z 時往右打方向，世界座標 x 必須變小，且 `laneAt` 要落在車道 2。

`curvature` 定義為「往 `right` 方向的轉率」，所以正曲率＝向右彎，
傾斜角、AI 內線都直接吃這個號誌。

## 賽道與國家

`buildTrack()` 把控制點做成封閉 Catmull-Rom 曲線，再以固定弧長（約 1.6 單位）重新採樣；
每個採樣點帶有切線、法線、曲率、傾斜與該處路寬，之後所有東西都讀這份資料
（路面網格、投影、AI、閘門位置）。

`layouts.ts` 提供六種版型，`nations.ts` 幫版型換上國家的調色盤、圈數與場景物件，
`tracks.ts` 把兩者組成 `TrackDef`。**新增一個國家只要一組調色盤 + 一份片語表**，
不必再畫一條賽道。

投影 `project(x, z, hint)` 用上一幀的採樣索引當提示，只掃描附近窗口，每隻鳥每幀 O(1)；
跳太遠會自動退回整圈掃描。

## 語言閘門（gates.ts）

`buildGateSet(track, nation, kind, laps, count, seed)`：

- 沿著賽道均分閘門位置，並閃開加速板（兩種獎勵不該用同一個轉向動作拿到）。
- **一次把每一圈、每一道閘門的題目都寫好**，由 seed 決定，所以重跑同一場會出一樣的題，測試也能重現。
- 三個選項一定互不相同、剛好一個正解；看板長相完全一致，不能從外觀猜答案。

五種題型，也就是巡迴賽的難度階梯：

| kind | 題目 | 練到的能力 |
| --- | --- | --- |
| `word` | 看中文選外語 | 詞彙辨識 |
| `listen` | 語音合成唸外語，選中文 | 聽力 |
| `number` | 用當地語言念數字 | 數字轉碼 |
| `recall` | 起跑前記 4 個詞，途中問「第 3 個是什麼」 | 主動回想／空間記憶 |
| `mixed` | 上面四種輪流出現 | 綜合 |

`recall` 是記憶宮殿的賽車版：詞語綁在「順序位置」上而不是意思上，
所以閘門問的是位置，不是翻譯。

判定完全由車道決定：`laneAt(lateral, halfWidth)` 把橫向位置切成三段，
超出路面回傳 -1（繞過閘門，不算對也不算錯）。對手用同一套規則過閘門——
`skill` 越高越常選對車道，所以「輕鬆」的對手會在閘門前送你名次。

## 巡迴賽與職級（campaign.ts）

八站：英國 → 日本 → 法國 → 西班牙 → 德國 → 韓國 → 沙烏地阿拉伯 → 俄羅斯，
題型從 `word` 一路升到 `mixed`，通關門檻（名次、正確率）只會越來越嚴。
每站要**同時**達到名次與正確率門檻才算通過，通過才解鎖下一站。

外交積分：名次分 + 語言分 + 首次通關獎勵。語言分的權重刻意調得夠重——
「拿冠軍但語言亂答」和「中段班但語言全對」大約等值，這是這個模式想主張的平衡。
積分累積成職級：見習通譯 → 通譯官 → 隨行外交官 → 首席外交官 → 特使 → 大使。

檔案（護照、答錯詞庫、生涯正確率）存在 localStorage 的 `chocorace.diplomat.v1`。

## 和 fluent-ai 其他部分的接點

- **記憶卡**：一場比完，結算卡列出這場答錯的詞，一鍵送進 `src/lib/memory-srs.ts`
  的間隔重複牌組（`addCard`），之後在 Memory Lab 正常複習。登入時用帳號 id，
  未登入用 `guest`。
- **語言清單**：`nations.ts` 的 `languageId` 對應 `src/lib/constants.ts` 的 `LANGUAGES`，
  所以巡迴賽的國家和 App 其他地方講的是同一組語言。
- **語音**：聽力閘門用瀏覽器的 speechSynthesis，語言標籤取自國家的 `speechLang`。

## 尚未做的部分

各國代表目前是賽場上的對手與檔案卡，還不是持續在線的 MMORPG 角色。
要往 MMORPG 走，現有結構已經留好接點：

- `仙境 3D`（`src/game/`）已經有 zone / NPC / 任務 / Supabase 同步的整套架構，
  可以把「各國大使館」做成 zone，代表做成該 zone 的 NPC，賽事當成 zone 內的活動入口。
- `campaign.ts` 的 `DiplomatProfile` 就是角色檔（職級、護照、答錯詞庫），
  把它從 localStorage 換成 Supabase 資料表即可跨裝置、可比較。
- `src/game/net/companions.ts` 已經有「有 Supabase 就同步真人、否則用模擬玩家」的模式，
  同一套可以搬來做多人同場賽事。

## 測試

`npm test -- src/game/race src/components/game/race`（不需要 WebGL）：

- 賽道：重採樣均勻度、投影正確性、起跑格、**座標系手性**。
- 物理：體力、離線速度上限、甩尾蓄力與回饋、碰撞、**轉向方向**。
- 比賽：完整比賽的圈速與名次、倒車不算圈、相同種子可重現、
  閘門結算（對／錯／繞過）、強對手的答題正確率高於弱對手。
- 閘門：題目結構、選項不重複、各題型的選項來源、記憶序列一致、可重現。
- 巡迴賽：職級門檻、解鎖鏈、積分權重、護照最佳值、答錯詞累計與去重、晉升偵測。
- HUD：題目橫幅、答錯才顯示正解、記憶序列編號、結算卡的積分與記憶卡按鈕。
